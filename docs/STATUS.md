## Реализовано, но требует устройств

- Android-сервер TLS с ключом AndroidKeyStore, кодом из 6 цифр, ограничением
  попыток и токеном. Windows хранит токен и отпечаток под DPAPI CurrentUser.
- USB: adb из установщика, сервер TCP только на loopback телефона, без кода.
- DNS-SD Android NSD и клиент ПК, общий список USB/Wi-Fi, ручной IPv4.
- Переподключение после успешного сеанса без остановки сервера телефона.
- Телеметрия: аккумулятор, зарядка, температура аккумулятора, thermal status,
  диапазон/сигнал Wi-Fi или USB; RTT управления не выдаётся за видеозадержку.
- Русская тёмная оболочка, проверка состояния уведомлений/ограничения батареи,
  экспорт журналов. Вендорный онбординг MIUI/ColorOS ещё предстоит в блоке E.

Фактическая совместимость AndroidKeyStore/TLS, NSD, USB-forward, FGS и поведения
прошивок **не подтверждена**. На Poco, OPPO и ПК пользователя ничего не запускалось.
Зелёная сборка не равна завершённой аппаратной проверке блока A.

## Регрессия обнаружения · 0.1.1 (аппаратная проверка A не пройдена)

Пользователь сообщил: телефон не появляется ни по Wi-Fi, ни по USB, несмотря на
перезапуски, включённую отладку и разные режимы USB. Модель телефона и журналы пока
не получены; **точная причина на его устройствах не установлена**.

Исправляются подтверждённые недостатки реализации:

- mDNS раньше использовал один выбранный ОС маршрут, один legacy unicast запрос
  и не имел локального правила firewall. Теперь запросы идут по всем активным IPv4
  интерфейсам, обычным multicast/QU и legacy способом, с ограниченными повторами;
  установщик добавляет/удаляет локальное UDP-правило только для частной сети.
- Отдельный adb daemon 5038 может конкурировать с существующим стандартным сервером
  за USB-интерфейс. Возврат к общему 5037. Очистка установщика теперь по точному пути
  процесса, без blanket kill-server чужих инструментов. CI проверяет сохранность
  чужого процесса adb при удалении.
- Карточка USB раньше зависела от успеха forward и shell/getprop. Теперь это только
  перечисление устройств и model из `devices -l`; forward только при подключении.
- Разделены сообщения Wi-Fi/USB; параллельные поиски одного транспорта исключены,
  USB больше не ждёт завершения Wi-Fi. stderr/stdout adb и счётчики mDNS журналируются.
- Android показывает адрес ручного подключения, подробности публикации NSD в журнале;
  отказ TLS не выключает уже подготовленный loopback USB-сервер.
- Добавлены регрессионные C#-тесты и CI-запуск подписанного APK в эмуляторах Android
  11/16 с настоящим KeyStore/TLS/FGS. Это не заменяет проверку на устройствах.

Новая версия ожидает CI и повторной проверки по обновлённому HARDWARE_TEST.md.
К блоку B не переходили. Предыдущие зелёные сборки не считаем доказательством
работы обнаружения после фактического отрицательного результата пользователя.

Первый прогон исправления: APK/lint/JVM и Windows/UDP/USB/установщик прошли CI.
Новая эмуляторная проверка завершилась ошибкой; её причина разбирается. Обнаружен

## Разрешённый отдельный цикл TLS · 0.1.2

CI 39081415604 остался красным: APK/Windows/установщик прошли, Android 11/16
отвергли TLS-рукопожатие. На Android 11 USB-loopback/телеметрия/команды прошли;
Conscrypt сообщил RSA internal error. Проверка официального AOSP/Conscrypt
выявила отсутствие разрешения DIGEST_NONE у ключа, необходимого для подписи
готового TLS-дайджеста, и NoPadding для raw RSA (PSS).

Исправление выдаёт эти разрешения при генерации, не добавляя расшифрование и не
ослабляя pinning на ПК. KeyInfo проверяет уже установленный ключ; несовместимый
заменяется и сбрасывает старый токен, совместимый сохраняется. После миграции
ранее сохранённое доверие на ПК нужно забыть и подтвердить новым кодом.

Регрессия CI расширена: чистая установка, неверные код/токен, TLS 1.2, обновление
с сохранением совместимого сертификата/токена, воспроизведение ошибки исходного
APK 79578cd и обновление поверх него без удаления данных. Результат этого цикла
нужно смотреть в Actions текущего коммита; до зелёного CI релиз не публикуется.
Аппаратный поиск Wi-Fi/USB по-прежнему не подтверждён. Блок B не начат.
