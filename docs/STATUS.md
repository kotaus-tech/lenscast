## Разрешённый отдельный цикл TLS · 0.1.2

CI 39081415604 остался красным: APK/Windows/установщик прошли, Android 11/16
отвергли TLS-рукопожатие. На Android 11 USB-loopback/телеметрия/команды прошли;
Conscrypt сообщил RSA internal error. Проверка официального AOSP/Conscrypt
выявила отсутствие разрешения DIGEST_NONE у ключа, необходимого для подписи
готового TLS-дайджеста, и NoPadding для raw RSA (PSS).

Исправление выдаёт эти разрешения при генерации, не добавляя расшифрование и не
ослабляя pinning на ПК. KeyInfo проверяет уже установленный ключ; несовместимый
заменяется и сбрасывает старый токен, совместимый сохраняется. После миграции
ранее сохранённое доверие на ПК нужно забыть и подтвердить новым кодом.

Регрессия CI расширена: чистая установка, неверные код/токен, TLS 1.2, обновление
с сохранением совместимого сертификата/токена, воспроизведение ошибки исходного
APK 79578cd и обновление поверх него без удаления данных. Результат этого цикла
нужно смотреть в Actions текущего коммита; до зелёного CI релиз не публикуется.
Аппаратный поиск Wi-Fi/USB по-прежнему не подтверждён. Блок B не начат.

## Разрешённый диагностический цикл C · 0.3.1

Обнаружена логическая зависимость от порядка независимых callback: ready ставился
только внутри обработки IDR и только если CaptureResult уже пришёл. Первый IDR,
пришедший раньше Camera2 metadata, не запоминался для ready. Ожидание следующего
IDR не является гарантией синхронизации API и может зависнуть при живых delta-кадрах.
Исправляется независимыми per-generation доказательствами CaptureResult + CSD + IDR,
проверяемыми из обоих callback-путей. Никакое доказательство не убирается и не
переносится со старой сессии. JVM-тесты проверяют все шесть порядков, reset и stale
callback; AVD делает три сброса с новым generation и новым CSD/IDR в видеосокете.

Добавлены однократные этапы в журнал и компактный proof в camera telemetry, без
диагностического экрана/изображений/секретов. При недоказанной готовности — ограничение
10 с с причиной и стадиями, не бесконечное ready=false при приходящих delta-кадрах.
Это доказанный дефект логики; подтвердить, что именно он проявился в AVD после reset,
можно только новым прогоном и порядком событий в журнале, не догадкой.
