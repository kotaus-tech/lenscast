# Блок B · «Экран» · 0.2.0

Связь блока A (0.1.2) принята пользователем: подключение по Wi-Fi и USB работает,
проблем не обнаружено. Это не подтверждение передачи изображения: её проверяем
отдельно ниже. Проверять Poco X3 NFC / Android 11 и OPPO Reno 15 / Android 16
по очереди; не приписывать одному телефону результат второго.

Установить APK и Setup.exe из **одного полностью зелёного Release 0.2.0** поверх
предыдущих версий. Удалять данные не нужно. При обновлении с исправленной 0.1.2
сертификат/токен должны сохраниться. Камера, микрофон и звук в режиме экрана не
используются. Веб-камера Windows появится в следующих блоках, не в этой сборке.

## Запуск и управление

1. На телефоне выбрать «Экран», нажать «Старт». Подключить ПК как в блоке A.
   Ожидаются телеметрия и прежнее доверие без нового кода для сопряжённого телефона.
2. На телефоне нажать «Разрешить показ экрана», подтвердить системный запрос
   **всего экрана**. На ПК открыть вкладку «Экран»: должно появиться изображение
   с правильными пропорциями и цветами. Чёрные поля не растягиваются в изображение.
   Записать разрешение, показанную частоту, кодек/декодировщик из нижней строки.
3. На телефоне нажать «Разрешить управление» и включить службу
   **«Lenscast · управление»** в специальных возможностях. Если прошивка блокирует
   доступ для установленного APK, разрешать ограниченные настройки только для
   своего Lenscast в сведениях о приложении. Не включать другие службы.
4. На ПК проверить одиночное нажатие, удержание 3–5 с, перетаскивание с видимым
   движением в процессе (не только после отпускания), прокрутку колесом.
   Координаты должны совпадать в центре и у четырёх краёв изображения.
   Нажатие на чёрное поле не должно нажимать на телефон.
5. Проверить «Назад», «Домой», «Недавние». Выключить службу управления на телефоне:
   изображение остаётся, жесты не выполняются, сообщение предлагает разрешить
   управление. Служба не получает содержимое окон, текст и ввод с клавиатуры.
6. Проверить полный экран, выход Esc и «Поверх окон». Начать перетаскивание и
   переключиться на другое окно ПК: на телефоне удержание должно завершиться.

## Длительная работа и разрывы

7. Не менее **30 минут** показывать весь экран: домашний экран, настройки,
   браузер, другие приложения. Ничего не записывать. Проверить сворачивание
   Lenscast на телефоне и возврат. Сохранить оба журнала после теста.
8. Во время трансляции открыть штатную камеру телефона, менять её режимы,
   вернуться домой. Показ экрана не должен останавливаться или открывать камеру
   самостоятельно. Защищённые Android/DRM окна могут быть чёрными: обхода нет.
9. Несколько раз повернуть телефон в обе ориентации, в том числе внутри штатной
   камеры. Изображение и координаты должны перестраиваться без повторного запроса
   MediaProjection, растяжения, зависания старого кадра и зажатого жеста.
10. Во время удержания отключить USB либо Wi-Fi. Активный жест должен завершиться;
    после восстановления связи картинка должна вернуться без нового разрешения
    показа экрана, если Android не остановил сам захват. Проверить также ручное
    отключение/повторное подключение ПК. Отправка команд не ждёт очередь видео.
11. Повторить пункты 2–10 через **Wi-Fi и USB**. USB проверить с выключенным Wi-Fi
    телефона. Для Wi-Fi отдельно отметить 2,4/5 ГГц и профиль домашней сети.
    При неподдерживаемом аппаратном декодировании допускается программный fallback;
    записать, что показывает интерфейс, не считать запрос DXVA доказательством GPU.
12. Нажать «Стоп» в уведомлении показа экрана, затем повторить запуск/разрешение.
    Служба, экран и управление должны остановиться. Отдельно остановить захват
    системной кнопкой Android: старое изображение убирается, повторный запуск
    требует нового системного согласия. На Android 15+ блокировка экрана может
    остановить MediaProjection по политике ОС; запросить согласие заново.
13. Повторно установить тот же APK поверх и проверить доверие Wi-Fi, запуск,
    остановку. Проверить обновление/удаление Setup.exe после USB: чужой adb не
    должен останавливаться. Камера/микрофон не должны запрашиваться режимом экрана.
14. Проверить окно ПК 760×580 и обычный размер, масштаб Windows 100/150/200%,
    портретный/альбомный показ и прокрутку Android. Контролы не перекрываются.

## Что прислать

- Телефон, версии Android/Windows/Lenscast, Wi-Fi 2,4/5 ГГц либо USB.
- Номера пройденных пунктов, длительность, точный текст ошибок и шаги воспроизведения.
- Разрешение, кодек и декодировщик, частоту кадров из интерфейса.
- Два файла «Настройки → Сохранить журнал» сразу после проверки. Можно приложить
  фото/скриншот и короткое описание видимой задержки. Программа сама ничего не
  записывает; измеренную сквозную задержку пока не обещаем.

Не присылать коды, токены, пароли или отладочные ключи. Журналы содержат локальные
IP/модель/USB-серийный номер: не публиковать их открыто.
