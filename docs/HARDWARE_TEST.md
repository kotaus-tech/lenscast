# Блок A · повторная проверка обнаружения, версия 0.1.1

**Предыдущая проверка не пройдена:** пользователь не обнаружил телефон ни по Wi-Fi,
ни по USB. Причина на его устройствах ещё не подтверждена журналами. К блоку B
не переходим. Изменения ниже устраняют найденные риски кода, но зелёный CI не
означает, что проблема на пользовательском ПК точно исправлена.

Установить APK и Setup.exe **из одного последнего полностью зелёного Release**.
Закрыть старый Lenscast перед обновлением ПК. APK устанавливать поверх: подпись
постоянная, удаление данных/сопряжения для проверки не требуется. В настройках
обоих приложений должна отображаться версия **0.1.1**.

## Сначала локализовать сбой

1. Написать, какой телефон проверяется: Poco X3 NFC или OPPO Reno 15 (если оба,
   проверять по одному). На телефоне нажать «Старт». Ожидаются «Ожидание ПК», адрес
   Wi-Fi, шестизначный код и уведомление со «Стоп». Если вместо этого сообщение об
   ошибке — сохранить журнал телефона, код не присылать.
2. На ПК вручную ввести адрес **с экрана Lenscast телефона**, ввести актуальный код
   и подключиться. Ожидаются название телефона и телеметрия. Записать, работает ли
   ручное подключение. Оно не зависит от mDNS и позволяет отделить поиск от TLS.
3. Проверить, что домашний Ethernet в настройках сети Windows имеет профиль
   «Частная» (только если это действительно ваша доверенная домашняя сеть).
   Брандмауэр полностью **не отключать**. На ПК нажать «Найти телефоны», подождать
   5–6 секунд. Телефон должен появиться в общем списке с отметкой Wi-Fi. Сохранить
   точный текст строки Wi-Fi под кнопками, если не появился. Два диапазона Wi-Fi
   на одном роутере допустимы; гостевая сеть/изоляция клиентов могут мешать.
4. Подключить телефон кабелем, оставить включённой отладку USB, разблокировать
   экран. Нажать «Проверить USB». Если запрос доверия появился на телефоне —
   подтвердить его и повторить поиск. Карточка USB должна появляться **даже до
   нажатия «Старт» на телефоне**: её поиск теперь не зависит от службы Lenscast,
   выполнения shell/getprop и создания перенаправления портов.
5. Если строка USB сообщает, что Windows не видит отладку, открыть Диспетчер
   устройств и проверить, нет ли неизвестного/ошибочного устройства телефона.
   Видимость MTP/файлов не доказывает, что установлен драйвер отладки. Прислать
   скриншот соответствующей ветки устройств и журнал ПК. Не ставить случайные
   драйвер-паки, не переключать все настройки разработчика подряд.
6. Выбрать карточку USB, нажать «Старт» в Lenscast телефона, затем «Подключиться»
   на ПК, без кода. Должны появиться телеметрия и отметка USB. Повторить с
   выключенным Wi-Fi телефона. Если USB-карточка появилась, но подключение не
   удалось, это уже отдельный этап: сохранить точное сообщение и оба журнала.

## Затем проверить устойчивость и установку

7. Для Wi-Fi повторно подключиться без кода. Выключить Wi-Fi на телефоне на 10 с,
   включить: после восстановления сети связь должна вернуться без кода.
8. Проверить уведомление телефона: статус меняется при подключении. Кнопки «Стоп»
   в приложении, уведомлении и на ПК останавливают службу. Сворачивание приложения
   и 5 минут ожидания не должны уничтожать сервер.
9. Если запущены Android Studio/другие инструменты с adb, повторить поиск USB с
   ними: Lenscast использует общий сервер 5037, а не конкурирующий 5038. Эмуляторы
   и беспроводная отладка не должны ошибочно появляться как USB-телефоны.
10. Сопрячь оба телефона по Wi-Fi по очереди. Забыть один: второе сопряжение должно
    сохраниться. Для забытого телефона снова нужен код. Пять неверных кодов вызывают
    паузу 30 секунд и смену кода; сам код не присылать.
11. После реального USB-подключения закрыть Lenscast, удалить его с ПК. Папка
    приложения, ярлык, журнал/доверие и правило «Lenscast: поиск телефона» удаляются.
    Чужой adb из другой папки не должен быть остановлен. При обновлении со старой
    версии собственный старый сервер 5038 должен быть остановлен установщиком.
12. Проверить окно ПК 760×580 и обычный размер, масштаб Windows 100/150/200%,
    настройки/прокрутку Android. Ничего не перекрывается. Видеопотока и камеры
    Windows пока **нет**; «отклик связи» — RTT управления, не видеозадержка.

## Что прислать при повторном сбое

- Модель телефона, версии Android/Windows и версия Lenscast на обеих сторонах.
- Номер пункта, ожидаемое/фактическое поведение, точный текст строк Wi-Fi/USB.
- Два файла из «Настройки → Сохранить журнал», **после** неудачного поиска.
- Работает ли ручное подключение по адресу (п. 2).
- Был ли системный запрос доверия USB; при необходимости скриншот Диспетчера устройств.

Журнал содержит технические сведения (локальные IP, модель/USB-серийный номер),
но не коды/токены. Не публиковать его открыто. Не нужно присылать код сопряжения,
пароли, отладочные ключи или включать беспроводную отладку.
