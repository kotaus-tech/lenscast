# Lenscast

Личный инструмент для Android и Windows 11 x64. Только тёмная тема, русский интерфейс.

## Текущее состояние

**Связь блока A принята пользователем: Wi-Fi и USB работают без проблем.**
Блок B · 0.2.0 добавляет показ всего экрана и жесты с ПК. Окончательная приёмка
блока B требует отдельной проверки обоих телефонов по HARDWARE_TEST.md; зелёный CI
не заменяет 30+ минут показа, штатную камеру и реальные драйверы/сеть.

Режим экрана: MediaProjection в отдельной foreground-службе, MediaCodec
(H.264; аппаратный HEVC выбирается только при наличии декодировщика на ПК),
отдельный TLS/USB видеоканал с одноразовым билетом текущего сеанса. Очереди
ограничены, при переполнении восстановление с IDR. На ПК Microsoft Decoder MFT,
попытка DXVA/D3D11 с программным fallback, NV12 → BGRA и WPF. Надпись DXVA
означает выбранный D3D-путь, не измерение фактической загрузки GPU.

Для начала: «Старт» → подключение ПК → «Разрешить показ экрана» на телефоне →
системное согласие всего экрана. Для жестов отдельно включить «Lenscast · управление»
в специальных возможностях. Нажатие/удержание/перетаскивание, колесо, навигация,
полный экран Esc и «Поверх окон» доступны на вкладке «Экран». Клавиатура на телефон
не передаётся. Захват не открывает камеру/микрофон, не пишет файлы и не обходит DRM.

Управление Camera2 и виртуальная камера Windows пока отсутствуют (блоки C–D).
Трей/автозапуск и измеренная сквозная видеозадержка — блок E. Показанные FPS —
счётчики кодирования/представления, «отклик связи» — RTT, не видеозадержка.

## Получение сборки

В GitHub Actions открыть **«APK и установщик Windows»**, выбрать зелёный запуск
с нужным коммитом и скачать оба артефакта. Только после успешных Android и Windows
jobs появляется предварительный Release с `app-release.apk` и `Lenscast-Setup.exe`.
Красная сборка не считается результатом работы.

APK подписан постоянным личным ключом `android/lenscast.keystore` (PKCS12), alias
`lenscast`, пароль `lenscast-personal`. Ключ намеренно в репозитории по ТЗ. Он не
подходит для публикации или иных приложений. Не заменяйте его, иначе обновление
поверх приложения перестанет работать.

## Сборка

Android: JDK 17, Gradle 8.13, Android SDK 36, Build Tools 36.0.0.

```sh
cd android
gradle :app:assembleRelease :app:lintRelease :app:testReleaseUnitTest
```

Windows: Windows 11 / Windows Server 2022, .NET SDK 8.0.415, Inno Setup 6.4.3.

```powershell
dotnet restore tests/Lenscast.Tests/Lenscast.Tests.csproj --locked-mode
dotnet publish windows/Lenscast/Lenscast.csproj --no-restore -c Release -o artifacts/windows
dotnet run --no-restore --project tests/Lenscast.Tests -c Release
# Положить platform-tools 36.0.2 (adb.exe, две DLL, NOTICE.txt)
# в artifacts/windows/adb, как в workflow.
& "${env:ProgramFiles(x86)}/Inno Setup 6/ISCC.exe" installer/Lenscast.iss
```

## Установка и подключение

1. Установить APK на телефон, разрешив установку из выбранного источника.
2. Установить Setup.exe на Windows, подтвердив запрос администратора.
3. На телефоне открыть настройки Lenscast, разрешить уведомления и работу в фоне.
4. Нажать «Старт». На ПК найти телефон либо ввести IPv4 из настроек Wi-Fi.
5. При первом подключении ввести код с телефона. Далее используется сохранённое
   доверие (DPAPI на Windows, закрытые данные приложения и AndroidKeyStore на телефоне).

Первое сопряжение — только в доверенной домашней сети. Самоподписанный сертификат
не удостоверяет личность до проверки кода; это не PAKE. При смене сертификата
автоматическое соединение прекращается. Гостевая сеть и изоляция Wi-Fi-клиентов
могут блокировать обнаружение/подключение. ПК подключён к роутеру Ethernet.

### USB

В сведениях о телефоне нажать 7 раз на номер сборки (MIUI: версию MIUI), включить
«Для разработчиков → Отладка по USB». Подключить кабель с передачей данных,
подтвердить доверие этому ПК. В Lenscast на ПК нажать «Проверить USB», выбрать
карточку и подключиться. Код не нужен. При нескольких телефонах оставить один.
`adb` входит в установщик и использует стандартный сервер на 127.0.0.1:5037,
чтобы не конкурировать с Android Studio и другими программами за USB-интерфейс.
При обновлении/удалении останавливаются только процессы adb, запущенные из папки
этой установки; чужой adb не останавливается. Перед обновлением или удалением
закройте Lenscast. Незашифрованный сервер доступен **только на loopback
телефона**, не в локальной сети.

## Журнал и удаление

На обеих платформах: «Настройки → Сохранить журнал». Windows хранит журнал и
защищённое доверие в `%LOCALAPPDATA%\Lenscast`; токены/коды не журналируются.
Удаление Windows-приложения убирает эту папку. На данном этапе регистрации COM
нет; она появится вместе с виртуальной камерой в отдельном блоке Г.

## Воспроизводимость и границы автоматических проверок

Версия .NET SDK закреплена в `global.json`, версии Actions — SHA, Inno Setup
6.4.3 проверяется SHA-256. NuGet и Gradle используют сохранённые lockfiles.
При намеренном изменении зависимостей lockfiles нужно обновлять отдельно;
обычный CI не пересоздаёт их. Android Build Tools — 36.0.0, platform-tools — 36.0.2.
Образы hosted runners могут обновляться: побитово одинаковый Setup.exe не обещается.

Сетевые тесты C# используют локальный сервер-имитатор: это проверка кадрирования,
heartbeat и переподключения, а не доказательство совместимости с MIUI/ColorOS.
JVM-тесты проверяют чтение частичных кадров и тайм-ауты; Camera2 пока отсутствует; MediaProjection/MediaCodec дополнительно
проверяются на AVD Android 11/16. Ни видеозадержка, ни стабильность на устройствах не измерены.

## Исправление TLS · 0.1.2

В 0.1.0/0.1.1 ключ AndroidKeyStore не разрешал подписание уже вычисленного
TLS-дайджеста. Conscrypt использует именно такой путь. Добавлены разрешения
DIGEST_NONE и raw RSA для PSS; это не отключает SHA-256 в TLS и не открывает
расшифрование приватным ключом (его назначение остаётся SIGN/VERIFY).
Несовместимый ключ заменяется один раз, старый токен удаляется. При ранее
сохранённом доверии на ПК нужно нажать «Забыть телефон» и сопрячься по новому
коду: проверка закреплённого сертификата не ослабляется. Совместимые ключи и
токены при последующих запусках/обновлениях сохраняются. Удалять APK/данные не нужно.

CI сравнивает исходный подписанный APK (79578cd) и исправленный: воспроизводит
обрыв TLS, затем проверяет обновление без удаления данных на Android 11/16.
Также проверяются чистая установка, TLS 1.2, отказ неверным коду/токену и
сохранность сертификата/токена при повторной установке исправленного APK.
Это регрессия TLS, а не доказательство работы аппаратного обнаружения.

## Если телефон не найден (версия 0.1.2)

- Нажмите «Старт» в приложении телефона. Код появляется после подготовки TLS,
  а адрес Wi-Fi виден прямо в карточке подключения. Попробуйте этот адрес на ПК:
  это отделяет проблему автопоиска от проблемы самого подключения.
- Для автопоиска домашняя сеть Ethernet в Windows должна иметь профиль «Частная».
  Установщик добавляет **только** локальное правило обнаружения UDP, только для
  Lenscast и только для частной сети. Брандмауэр целиком не отключается. Гостевая
  сеть/изоляция клиентов на роутере могут по-прежнему блокировать обнаружение.
- Под кнопками поиска отдельно показываются результаты Wi-Fi и USB. Отказ adb
  больше не маскируется общим сообщением «телефон не найден». Если Windows вообще
  не видит интерфейс отладки, одного переключения MTP/передачи файлов недостаточно:
  проверьте драйвер телефона в Диспетчере устройств. Используйте только официальный
  драйвер производителя, не случайные «пакеты драйверов».
- В журнал Windows пишутся выбранные сетевые интерфейсы, счётчики ответов mDNS,
  вывод и код завершения adb. Там есть локальные IP/имя модели/серийный номер USB;
  журналы не предназначены для открытой публикации. Коды сопряжения, токены и
  содержимое экрана не журналируются.

CI дополнительно запускает подписанный APK на эмуляторах Android 11/16 и проверяет
реальный сервер: foreground service, USB-loopback, TLS/AndroidKeyStore, сопряжение
и переподключение по токену. Это не проверка Windows USB-драйвера и не проверка
физического Wi-Fi между Ethernet-ПК и телефонами. Прежняя аппаратная проверка
обнаружения не пройдена; окончательный результат требует повторной проверки.
